The role a critic is selected by is now read from the gate configuration
rather than fixed in the dispatcher.

A program that configures a different role for its proposal-critique gate
gets that role honoured. Previously the dispatcher supplied its own value,
which took precedence, so a gate configured one way in the file behaved
another way in practice — and only on that one path.

A consequence worth stating: a gate configured to select by role must now
declare both the roles table and the role to select by, or the configuration
is rejected when it is read. That rejection replaces a situation where the
same misconfiguration produced no reviewer at run time, with nothing said
about why.
