A task that has already been assigned and not yet answered is no longer
assigned again every time the task list is updated.

Only a filed completion used to stop a reassignment, so work that was
dispatched and still in progress — the ordinary case — was re-sent on every
subsequent change to the task file. On this installation that accounted for
just over half of all assignment traffic, with some tasks assigned seven
times.

An assignment the recipient has acknowledged as done is still re-sent when no
completion was ever filed. That is deliberate: the absent filing is the real
problem, and suppressing the reassignment would conceal it.

The run now reports already-assigned separately from already-completed, since
a correct skip and a stalled assignment nobody is acting on need different
responses.
