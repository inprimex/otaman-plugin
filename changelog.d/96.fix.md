An approval check that cannot be carried out now stops the dispatch under
every setting, not only the strictest one.

The previous release refused only where the project had opted into strict
enforcement. Warning mode is the default, so in the common case an
unreadable approval record still let work go out unchecked — the very thing
the earlier fix set out to stop.

The decision now comes from one shared implementation rather than being
worked out separately here, since telling an absent record apart from an
unreadable one is the whole difficulty and is easy to get subtly wrong in
two places. Installations running an older core keep the same refusal.
