`otaman doctor` now reports whether your running sessions and daemons are
actually running the configuration on disk.

Every other check inspects files, which is why a fleet could run for five
days on stale hook wiring while doctor stayed green: the files were all
correct, and nothing compared them against what the live processes had
loaded. The new runtime-freshness section names each stale session, the
input that moved, and the remedy.

It reports and never restarts anything — relaunching a session destroys
in-progress work, so that stays a human decision. Editing a hook script
does not mark a session stale, because script bodies are read fresh on
every call; only settings captured when the session started can go out of
date. A session or daemon that cannot be inspected is reported as
unchecked rather than assumed healthy.
