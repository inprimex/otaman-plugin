Task dispatch no longer re-assigns work that has already been reported
complete.

Completing a task files a message on the bus; the checklist file is
ticked separately, on a later sweep. Any specs push in between re-sent
finished tasks to the agent who had just finished them — one agent was
re-assigned the same task twice in an afternoon. An agent with less
context would have redone the work.

Dispatch now treats a task with a filed completion as done, and says so:
skipped tasks are counted and named in the dispatch summary rather than
quietly omitted. A completion note it cannot read confidently is ignored,
so the task is re-sent rather than silently dropped.
