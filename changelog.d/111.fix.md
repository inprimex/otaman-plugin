Specification-change notices now explain why their recipients were chosen,
and name the change in a field of its own.

The notice carried a fixed sentence describing when routing falls back to a
default. Five different situations produce that same default, so the
sentence was wrong in four of them — including the one that matters most, an
annotation naming a repository that does not exist. A reader was told the
change assigned nobody when in fact the routing could not find the person it
named.

The reason is now computed by the same code the command-line tool uses, so
the two cannot describe the same routing differently. Where no interpreter
is available the notice says the reason was not determined, rather than
asserting one.

The change name also appears as its own field instead of only inside a file
path, which previously had to be parsed out of most notices.
