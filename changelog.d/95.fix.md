A dispatch whose approval gate could not be read now says so.

Each change carries a small file recording how far it has been approved.
If that file was present but unreadable, work was handed out as though the
check had passed, and nothing was reported — which is how five agents were
once assigned work on a change nobody had approved.

Handing out the work still goes ahead, since an unreadable file should not
be able to stop the system dispatching at all. What has changed is that the
run now states plainly that no approval check happened, gives the reason,
and names the command that answers the question properly. A change that
simply has no such file is a different matter and stays quiet, as before.
