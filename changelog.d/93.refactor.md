The dispatcher no longer keeps its own copy of the filed-completion reader.

Deciding whether a task has already been reported complete — and whether a
later withdrawal has made that report stale — now happens in one place,
shared with the command-line tools that make the same judgement. Two copies
of a rule this subtle drift apart exactly when it matters, which is when a
completion has been retracted.

If the installed core is older than the dispatcher and cannot supply the
reader, dispatch continues and every task goes out, with a warning saying
the check did not happen. An unchecked run and a clean one both assign
everything; only one of them is correct, so they must not look alike.
