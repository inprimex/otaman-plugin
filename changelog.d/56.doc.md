Repositories scaffolded by `otaman init` now carry a `changelog.d/`
folder explaining how to write a release-notes fragment: one short,
customer-facing file per pull request, named `<pr>.<category>.md`.

Release notes are assembled from these fragments alone, so what you
write is what readers see — nothing is summarized out of commit
messages or pull-request descriptions. Documentation-only changes can
opt out instead of inventing an entry.
