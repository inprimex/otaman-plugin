Repositories scaffolded by `otaman init` now learn how to *clear*
changelog fragments, not just how to write them.

After a release cut, the generated `changelog.d/README.md` explains
that the cut names exactly which fragment files it consumed, and that
those named files are what gets deleted — never a glob, and never by
emptying the directory. The record of what a release consumed, rather
than the state of the folder, is what prevents a note from appearing
in two releases.
