Task assignments now carry the change's delivery authorization envelope.

An agent receiving work can see which action classes the change
authorizes, and their scope, without going to read the specifications
repository.

The listing is deliberately blunt about what it does not grant: a class
the agent runtime still prompts for is shown as not proceeding
unprompted, because a declaration that over-promises is worse than none.
An envelope that cannot be read, or that names something never
pre-authorizable, is carried not at all and the reason is reported.
